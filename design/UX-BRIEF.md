# PartyGame 手机网页交互说明

状态：用户批准的桌游俱乐部方向已实现。本文描述当前代码行为；原 PDF 是历史视觉参考。浏览器与服务端验证不替代实体手机验收。

## 目标与使用场景

2–12 名朋友各自用手机进入同一局。入局、投稿和查看任务应简短清楚，让玩家回到线下互动。本人知道秘密任务，不知道未解除的隐藏禁忌。

## 三种模式

| 模式 | 本人可见 | 他人可见 | 猜中后 |
| --- | --- | --- | --- |
| 秘密任务 | 自己的触发条件和动作 | 不显示其他人的秘密任务 | 继续生效 |
| 隐藏禁忌 | 自己的状态，条件保密 | 其他玩家的禁忌条件 | 本人的禁忌解除，条件可见 |
| 混合模式 | 同时遵循两套权限 | 同时遵循两套权限 | 两种状态独立 |

## 条件与后果随机重组

- 创建房间时可选，默认关闭；没有该设置的旧房间也保持关闭。房主仅可在准备阶段修改，修改后全员需重新准备；其他玩家可查看当前规则。
- 开启后，所有启用的秘密任务（含内置题）拆成条件和后果再配对。每份素材最多使用一次，排除原配对与重复新题；隐藏禁忌的分配、作者回避和可见范围不变。
- 秘密任务投稿使用「提供条件和后果」「触发条件」「执行后果」等素材文案。预览说明分别入池，任务池分行展示，不暗示这组内容会原样发出。
- 无法组成每人一张新题时禁用开始按钮并说明原因。可补充不同的条件和后果、开启内置题库，或关闭重组后重新准备。
- 已发出的实际配对随房间保存，刷新或服务器重启不重抽。隐藏禁忌单一模式禁用该开关并解释不受影响。

## 页面与操作

| 页面 | 当前行为 |
| --- | --- |
| 入口 | 加入、创建、规则；邀请链接预填房间码 |
| 加入 / 创建 | 昵称与 12 款头像；创建时选择玩法、内置来源及可选重组；头像选择为六列两行 |
| 房间大厅 | 邀请链接与二维码、玩家状态、题量、当前重组规则、准备；房主可在开局前进入设置，全员准备且任务可分配后开始 |
| 任务池 | 分类题量、来源、本人投稿；重组时分别展示条件和后果素材；自己的投稿支持编辑与删除 |
| 投稿 | 秘密任务分开填写条件与动作，重组时明确为独立素材；禁忌填写本人触发条件；服务端成功后卡牌进入可见牌堆 |
| 分配完成 | 显示已成功分配的一张或两张牌；可跳过洗牌动画进入游戏 |
| 我的任务 | 秘密任务默认遮住，按住 / 键盘按住查看，松开隐藏；另有点按查看 / 收起 |
| 大家的禁忌 | 展示其他玩家的完整条件与解除状态，排除自己；确认猜中前再次说明后果 |
| 本人禁忌解除 | 显示打开的封印和本人的条件；混合模式提醒秘密任务继续 |
| 房间菜单 | 成员、规则、退出及房主结束入口；与「收起」动作分离 |
| 结束确认 | 明确告知全部任务将公开；保留继续游戏选项 |
| 本局揭晓 | 扇形牌堆与逐玩家回顾；房主返回准备再开一局 |

## 保密交互与角色

- 服务端为每名玩家分别构造 HTTP 和 SSE 数据。未解除的本人禁忌不下发；其他人的秘密任务直到结束才公开，房主没有额外查看权。
- 秘密正文按查看状态挂载，按压取消、失去指针捕获、窗口失焦、页面隐藏和离页事件均有收起处理。顶部「收起」还会遮住当前可见任务，恢复时需要玩家主动返回游戏。
- 投稿只向本人展示；禁忌分配回避作者。作者仍然知道自己写过的条件，不能宣称完全消除知情。
- 另一名玩家按现场判断确认禁忌猜中；应用不自动识别行为，也不执行惩罚。
- 游戏中不接纳新玩家。已有身份重连保持原牌；房主主动退出会转移权限。结束回顾保留本局参与者。
- 玩法、任务来源、重组规则或投稿变化会重置准备。人数、准备或任务不足时保留阻止开局的原因。
- 错误信息在页面或对话框中显示；邀请复制失败提供可选取的链接，不以成功提示掩盖失败。

## 布局与可访问性

单列应用最大宽度 442px，桌面居中。600px 及以上增加外侧留白和容器阴影；359px 及以下收紧页边距和非关键字级。主要按钮最小高度 56px，图标操作最小 44px；安全区通过 CSS 环境变量参与页边距。12 款头像使用稳定 ID，大厅超过六人改为三列网格。

任务正文自然换行。秘密内容为 23px / 900，小屏 21px；其他禁忌、投稿预览和回顾任务为 18px / 700。两类任务同时用名称、图标和颜色区分。原生表单、可见焦点、语义按钮和点按替代方式已存在；不能由此推断屏幕阅读器、实体手机触控或系统后台行为已全面验证。
