# 有猫腻 · Fishy

按照 [UI 设计稿](output/pdf/PartyGame-UI-Design.pdf) 实现的手机聚会游戏。每人用自己的手机，在同一 Wi-Fi 下进入同一个房间。

## 启动

需要 Node.js 22.12 或更新版本。

```sh
npm install
npm run build
npm start
```

电脑打开 `http://localhost:4173`。创建房间后点「邀请朋友」，页面会提供当前电脑的局域网链接与二维码。其他手机连接同一 Wi-Fi 后打开这个链接，填写昵称即可加入。电脑需要保持运行、避免睡眠；访客 Wi-Fi 如果开启设备隔离，手机可能无法访问电脑。这里没有部署公网服务。

开发时使用 `npm run dev`；改端口可以运行 `PORT=4174 npm start`。

## 游戏流程

- 2–12 人，各自选昵称和 12 款头像之一。选择秘密任务、隐藏禁忌或混合模式；混合模式每人各一张。
- 内置两类任务各 30 道，所有人都能添加/编辑/删除自己的投稿。其他人的投稿内容保持私密。
- 创建时可开启「条件与后果随机重组」，默认关闭。所有启用的秘密任务（含内置题）拆开后重新配对；隐藏禁忌保持原规则。
- 每个人准备后，由房主开始抽签。房主可在开局前修改重组开关；修改玩法、题库来源、重组规则或投稿后需重新准备。
- 秘密任务默认收起；按住查看、松手隐藏，也可以用点按方式切换。被猜出后继续生效。
- 本人的隐藏禁忌在猜中前不会下发到本人的手机；其他玩家可查看，并在现场判断后确认猜中。猜中只解除该禁忌。
- 房主确认「结束并揭晓」后才公开所有任务。可返回准备状态再开一局。

重组开启时，投稿页和任务池展示的是分别入池的条件与后果素材，不是即将发出的完整任务。每份素材最多使用一次，不发出启用题库中的原配对或重复新题。素材不足以组成每人一张新题时会阻止开局，可补充不同的条件和后果、开启内置题库，或关闭重组。

游戏中的新玩家需等待下一局；已加入的玩家刷新或重连会恢复同一身份。主动离开的房主会把房主身份交给下一位剩余玩家。游戏中的离开不会取消已经发出的牌；结束回顾保留本局参与者。

## 保存与权限

房间保存在本机 `.data/rooms.json`，未操作 24 小时后过期；重组设置与实际发出的配对一并保存，刷新或服务器重启不重新发牌。没有重组设置的旧房间默认关闭。身份凭证采用 HttpOnly Cookie，磁盘仅保存凭证摘要。每个玩家的实时更新都在服务端分别过滤；房主没有偷看其他秘密任务的特权。请勿提交 `.data` 或把开发服务器直接暴露到公网。

这一版使用单个 Node.js 进程和本地持久化，适合聚会现场。多人公网部署需要另行配置 HTTPS、反向代理及服务器运行方式。

## 验证

```sh
npm test
npm run build
```

当前 16 项自动测试与生产构建通过。覆盖三种模式、投稿回避、分配失败的原子性、信息可见性、猜中和揭晓权限、身份恢复、持久化、准备与房主转移、HTTP 身份验证和实时更新，以及 12 名不同头像玩家的完整回合。重组测试覆盖内置题与投稿共同入池、原配对及重复新题排除、素材使用次数、房主权限与准备重置、失败恢复、旧房间默认值，以及重启后的实际配对保留。

跨主机 API 与浏览器流程已经验证；已有 320、390、442、1280、1440 宽度截图。实体手机触控、系统后台遮盖和减少动态效果的独立运行验收仍待完成，视觉复核所列修正已通过定向验收。

本次重组功能另有隔离浏览器与独立玩家流程检查，以及覆盖 320、390、1280 宽度的 14 张截图，范围内的视觉评审结论为可交付。历史入口的机械响应式比对仍未关闭，该结论不扩大到实体手机验收。

## 设计与素材

设计与页面说明见 [design/README.md](design/README.md)。实现用插画在 `public/assets/`，由内置 ImageGen 按原稿生成，已去除本机路径的提示词保存在 [design/prompts/implementation/](design/prompts/implementation/)。12 款头像在大厅、游戏和揭晓页复用固定身份。Noto Sans SC 字体自托管，图标使用 Lucide。当前实现的 token 与组件规则见 [DESIGN.md](DESIGN.md)。

项目已在用户指定的私有服务器部署；公开仓库保留 [Docker 部署模板](deploy/README.md)，不包含实际部署地址。

## 公开仓库前检查

使用 Git 提交本项目，不要直接上传整个工作目录。`.gitignore` 排除了房间数据、测试 Cookie、环境文件、部署备份及本地设计审阅记录。实际部署参数只保存在服务器或被忽略的本地文件中，公开模板见 [deploy/README.md](deploy/README.md)。

首次提交前检查 `git status --short --ignored` 和 `git diff --cached`，确认没有 `.data/`、`data/`、`tmp/`、`.env` 或身份凭证。忽略规则不会移除已经提交的文件；若凭证曾被公开，需要使相应身份失效并清理 Git 历史。
